# VowFrame 提示词规范（V3.10）

本文是生成提示词的唯一依据。`backend/app/prompts.py` 必须与本文逐字一致；要调整提示词，先改本文，再改代码。

已创建的任务保存创建时的提示词快照，修改本文只影响之后新建的任务（PRD 15.4）。

**V3 相对 V2 的变化**（2026-10-27，依据真实照片对比实验）：

- AI 导演从只写「动作瞬间」改为写完整的「镜头」：机位与焦段、构图、人与场景、光、瞬间。V2 把构图拆成没人负责的空白，模型默认画成居中、正面、平视、人物占满画面的合影。
- 风格段从「一句场景 + 照亮面部的补光」改为「服装 + 场景素材与场景光源」。V2 每个风格都写「照亮两人面部」，模型会给人物单独打一道和场景无关的正面光，人物像贴在背景上。
- 新增固定的「画面质感」段，要求人物与环境处在同一光源下，并有接触阴影。
- 导演的面部约束只保留底线，不再要求「每张至少一人看向镜头」。

**V3.1**（2026-10-27）：

- 每个风格从「一个固定场景」改为「视觉语言 + 3～5 个场景变体」。一个风格只有一个场景时，拍 20 张只能在同一个空间里换角度，整组单调；「高级光影」更被错误地定义成「深灰影棚 + 一盏聚光灯」，灯被当成道具拍进画面。高级光影的本质是光影本身，背景颜色不限，光源不入画。
- 导演按参考方式选择场景：「只用两人照片」时可在全部变体中选择；「两人照片 + 样片」时只用样片所在的第一个变体，避免与样片参考图冲突。
- 风格从 6 个扩充到 14 个。

**V3.2**（2026-10-27）：

- 表情默认含蓄：浅笑或微笑，可以微微露齿，但不咧嘴大笑；导演明确写出「开怀大笑」的镜头例外。此前没有任何一段约束笑容的程度，导演又常写「忍不住笑」「笑起来」，生图模型按欧美图库的习惯画成露齿大笑，既不符合东亚婚纱照含蓄的审美，大笑也会改变脸颊和眼部形状，让成片不像不笑的参考照片。
- 没有用「东亚婚纱照」这类词：它容易被理解成人种描述，把两人的脸推向平均模板，与「长相第一」冲突；要管的是笑容，就直接写笑容。

**V3.3**（2026-10-27）：

- 画幅从全局固定改为按镜头决定：AI 导演为每个镜头选竖版或横版（以竖版为主，交代环境的远景用横版），具体比例由设置中的「画幅比例」决定（竖版 3:4 / 2:3 / 9:16，横版为同一比例横过来）。比例是构图的一部分，导演负责构图却不能决定横竖，远景只能硬塞进竖版。

**V3.4**（2026-10-27）：

- 景别从影楼说法「全身 / 七分身 / 半身 / 近景」改为摄影的五级景别「远景 / 全景 / 中景 / 近景 / 特写」，并新增不露脸的「局部特写」（手、戒指、捧花等）。旧的四个选项只按「人露出多少」划分，缺了最能体现导演功力的两头：人很小、环境为主的远景，和情绪或细节的特写；导演每个镜头都被迫归进这四类。旧作品上的「七分身」「半身」仍可读取和显示，新镜头不再使用；尚未拍摄的旧方案读取时改为中景。
- 局部特写画面里没有人脸：画面质感段换成不要求面部的版本；不做自动换脸，也不能加强长相或手动换脸。
- 表情规则改为「表情自然、真实，符合这个瞬间的情绪」，取消 V3.2 的「默认含蓄、不露齿大笑」。换脸强度降到 0.5 后，表情不再被参考照片抹掉，按瞬间的情绪自然表现即可。

**V3.5**（2026-10-27，审阅港风远景「街口等一步」的完整提示词后）：

- 远景单独使用一段画面质感：人物按镜头描述的大小出现，不为看清面部而放大，面部清晰可辨即可。此前远景只有镜头里一句「人物约占画面五分之一」在要求人小，而人物锁定段、「两人面部曝光充足、清晰」、避免项「面部被遮挡」、样片参考图和导演写的「面部朝镜头四分之三侧向」都在把人往大里推，远景常被画成全景。人物锁定段不改：问题是「画多大」，不是「像不像」。
- 导演不再在镜头里重复声明「面部无遮挡」「面部清晰可见」（这条底线已在其他段落里），远景里不写面部朝向的细节。
- 通用避免项把「文字和水印」拆为「叠加在画面上的标题文字、水印、乱码文字」。港风老街、城市夜景等场景本来就有招牌文字，整体避免文字会让模型把招牌画空或画成乱码；真正要避免的是后期叠加的文字、水印和乱码。

**V3.6**（2026-10-27，参考他人的婚纱提示词后）：

- 造型统一：每个风格的服装从一句话扩为完整造型（新娘的发型、妆容、配饰、婚纱领型面料裙摆；新郎的发型和服装），并要求「同一组照片里，两人的服装、发型、妆容和配饰保持完全一致」。此前服装只有一句，其余细节由生图模型每张自由发挥，同一组里婚纱领型、头纱、发型张张不同，像几次不同的拍摄拼在一起。造型只写妆容和服饰，不写五官（例如写唇妆颜色，不写唇形）。
- 动作张力：导演规则从「避免夸张特技」改为允许奔跑、旋转、托举、相拥转圈、裙摆头纱飞扬等有张力的动作；整组要求加上情绪起伏，既有安静甜蜜的瞬间，也要有一两张有张力的画面。此前整组几乎都是牵手、对视、轻靠，缺少起伏。
- 画面质感三段都加上「电影感，极致细节，高级质感」（用户决定）。导演规则不再禁止这类词，只说明画质已写在画面质感段里，镜头里不必重复。

**V3.7**（2026-10-27）：

- 导演规则第 2 条点明会挡脸的动作（捂嘴、打喷嚏、用手托脸、把脸埋进对方肩头），不要写。实测中导演写出「闻花时打了个喷嚏」，生成的画面里新郎用手捂住了半张脸：规则只说「面部不被手遮挡」，导演构思小事件时没意识到动作本身会挡脸。
- 写法示例从安静的「耳边悄悄话」换成有张力的「抱起转圈、裙摆头纱扬起」。导演会照着示例的力度写；生图模型又会把动作画小一档（实测「奔跑」画成快步走、「转圈」画成牵手站定），示例更有力，落到画面上才有动感。

**V3.8**（2026-10-28）：

- 人物重新成为画面主体。V3 以来的改动都在给环境加分量（导演五项里三项写环境、要求写「留白在哪里」、每个风格 3～5 个元素丰富的场景变体、整组要求交代环境的远景），却没有任何一句说「人是主角」；V3 以前人物突出只是「面部清晰」「并排面对镜头」这些已被去掉的写法的副作用。结果成片普遍是环境满、人物偏小偏边。
  - 导演提示词开头讲明「婚纱照的主角永远是这对新人」：先想情绪和两人之间发生的事，再选景别、构图和光去表现；环境交代一两句即可；除远景外两人占画面主要部分；「瞬间」是镜头的重点。去掉「留白在哪里、有没有前景」这类会诱导固定构图的要求。
  - 画面质感加「两人是画面的主体，环境、光影和留白只是衬托」；远景版加「人物仍是画面的视觉焦点」。
  - 整组景别以全景、中景、近景为主，远景最多一两张。
- 去掉写法示例，动作规则也不再列举具体动作。实测导演会照搬示例和列举（示例写「抱起转半圈」，下一组就出现「抱离地面转过半圈」），每组趋同；构图和动作交给导演自己判断。

**V3.9**（2026-10-28，法式复古一组新郎普遍不像后）：

- 新郎发型不再指定为背头。法式复古、高级光影、港风复古、闪耀晚宴、黑白经典原来写「背头 / 侧分背头」，改为「保持参考照片中的发型轮廓和发际线」，再按风格写打理方式。男性没有妆容区分，发型和发际线是辨认新郎的主要依据之一；指定背头又和人物锁定段的「发际线一致」冲突，模型会按「背头 + 礼服」重画一张通用的复古男主脸。同一项目、同一模型对比：写「干净利落的短发」的简约风格新郎像，写「复古侧分背头」的法式风格新郎不像。换脸只替换五官区域，改不回发型和脸型，所以要在出图这一步解决。新娘同理：每个风格的新娘发型前加「保持参考照片中的发际线和分缝」，盘发、编发、卷发等造型照旧（只改变脑后和发尾，不改变正面辨认的轮廓）；与之冲突的「额前留少量自然碎发」（简约）和「侧分」（港风复古）去掉。
- 通用避免项加「男模脸、偶像剧男主脸、下颌被削尖、脸型被拉长」。原避免项（网红脸、幼态脸等）都针对新娘的偏移，新郎被理想化成男主角模板时没有任何约束。

**V3.10**（2026-10-28，用户决定回到 V3.4）：

以 V3.4 为基础，只保留后来两项改动，并去掉局部特写：

- 去掉不露脸的「局部特写」（`detail`）：导演不再写这类镜头，画面质感段回到一段。旧作品里已有的局部特写仍可读取和显示，也仍然不能加强长相或换脸；尚未拍摄的旧方案里的局部特写读取时改为近景。
- 保留 V3.6 的「电影感，极致细节，高级质感」。导演规则第 7 条同时采用 V3.6 的写法（画质已写在画面质感段里，镜头里不必重复），不再把这些词称为「空洞的形容词」，避免和画面质感段自相矛盾。
- 保留 V3.6 的完整造型和「同一组照片里，两人的服装、发型、妆容和配饰保持完全一致」，造型文字为 V3.6 原文（不含 V3.9 的发型改动）。
- V3.5、V3.7、V3.8、V3.9 的其余改动全部撤回：远景专用画面质感段、避免项里的文字拆分和男模脸、动作张力与挡脸动作规则、写法示例的更换、「人物是画面主体」等。导演的写法示例回到 V3.4 的「耳边悄悄话」。

## 1. 设计原则

1. **长相第一**：人物锁定段永远放在最前面，任何风格、镜头描述都不得削弱它。
2. **绝不描述五官**：真人长相由参考照片决定。提示词里只写「保持一致」，不写「大眼睛」「高鼻梁」之类的五官描述，否则文字会和照片打架，模型折中后就不像了。
3. **说清楚能改什么**：明确允许改变发型、妆容、服装、姿态、场景、光线，减少模型对五官「下手」的空间。
4. **一个完整的镜头**：每张照片由导演写清楚怎么拍（机位、焦段、构图、人与场景、光）和拍到了什么（一个真实发生的小事件）。构图不设限制。
5. **同一光源**：光线只来自场景里真实存在的光源，同一束光同时照在人物和环境上；面部曝光由「画面质感」段统一保证，而不是给人物单独补一道光。
6. **正面约束 + 避免项**：gpt-image 与 Gemini 没有独立的负面提示词参数，避免项写在提示词最后一段。

参考：[female-portrait-director](https://github.com/liyue-aigc/female-portrait-director) 的参考图锁定、导演门禁与失败诊断规则。我们没有采用它的「五官方向描述」（原因见原则 2）。

## 2. 提示词结构

每条提示词由六段组成，段落之间空一行：

```text
{画幅}

{人物锁定}

{服装与风格}

{镜头}

{画面质感}

{避免项}
```

### 2.1 画幅

比例按以下规则决定，再按下表写成文字：

- **样片**：始终是竖版，使用设置中的竖版比例。
- **拍组和换动作**：使用导演为该镜头选的 `orientation`。竖版用设置中的竖版比例，横版用同一比例横过来（3:4 → 4:3，2:3 → 3:2，9:16 → 16:9）。
- **重新生成、加强长相、换景别**：沿用原作品的比例（记录在任务的模型配置快照 `aspect_ratio` 中），即使之后修改了设置。同一张作品的各个版本因此保持相同画幅。

| 比例 | 文字 |
|---|---|
| 高 > 宽（如 3:4） | `竖构图，{比例} 比例的写实婚纱照。` |
| 宽 > 高（如 4:3） | `横构图，{比例} 比例的写实婚纱照。` |
| 1:1 | `方构图，1:1 比例的写实婚纱照。` |

同一个比例也会作为参数传给生图模型（gpt-image 的 `size`、Gemini 的 `aspect_ratio`），文字和参数一致。

### 2.2 人物锁定

**只传两人照片时（样片、`prompt_only` 拍组）：**

```text
图片角色：第一张图是新娘的身份参考，第二张图是新郎的身份参考。严格保持两人的长相：脸型、五官比例、眼型、鼻型、唇形、肤色、发际线和年龄感都与第一、二张参考照片一致；不要美颜、瘦脸、磨皮或改变五官。允许改变的只有发型造型、妆容、服装、姿态、场景和光线。风格要求与长相冲突时，以长相为准。
```

**传两人照片 + 样片时（`with_preview` 拍组）：** 在上一段的「第二张图是新郎的身份参考。」之后插入：

```text
第三张图是风格参考，只参考它的场景、服装、光线和色调，不参考其中的人脸、长相和构图。
```

### 2.3 服装与风格

```text
服装与风格：{该风格的服装}同一组照片里，两人的服装、发型、妆容和配饰保持完全一致。{该风格的视觉语言}
```

样片和旧版固定动作（第 4 节）没有导演写的场景，在这一段末尾再加上该风格的**第一个场景变体**：

```text
场景：{第一个场景变体}
```

AI 导演写的镜头已经包含所选场景，不加这一句。风格段**不写机位、构图、景别和人物动作**，这些由「镜头」决定。

### 2.4 镜头

- 样片：使用第 4.1 节的固定镜头。
- 拍组与换动作：`镜头：` + AI 导演写的镜头正文（第 7 节）。
- 旧作品（`pose_id` 非空，或快照里是「动作瞬间：」）的重新生成：沿用任务快照中保存的原提示词，不重新组合。
- 为什么场景写在镜头里而不是风格段里：同一风格的不同镜头可能在不同的场景变体里拍，只有导演知道每个镜头选了哪个。

### 2.5 画面质感

所有风格、所有镜头共用（样片、旧版固定动作和 AI 导演写的镜头）：

```text
画面质感：真实相机拍摄的婚纱摄影作品，电影感，极致细节，高级质感。人物与环境处在同一光源下，受光方向、色温和明暗一致，人物脚下或身后有自然的接触阴影；两人面部曝光充足、清晰；表情自然、真实，符合这个瞬间的情绪；焦外自然虚化，色彩处理统一，皮肤保留真实质感。
```

### 2.6 避免项

```text
避免：{通用避免项}、{该风格避免项}。
```

通用避免项：

```text
网红脸、整容脸、幼态脸、五官欧美化、过度磨皮的塑料皮肤、面部被遮挡、多余的人物、手部或手指畸形、人物像抠图贴在背景上、影楼廉价感、文字和水印
```

## 3. 风格

界面显示的名称和简介如下表；发给模型的是「服装」「视觉语言」和「场景变体」。第一个场景变体是该风格的默认场景，用于样片（第 2.3 节）和「两人照片 + 样片」模式下的导演（第 7.2 节），所以它应当是这个风格最有代表性、光线最利于看清面部的场景。

每个场景变体写清背景和光源，光源本身是否入画遵循视觉语言；不写机位、构图和人物动作。

| 编号 | 名称 | 界面简介 |
|---|---|---|
| `korean_minimal` | 韩系极简 | 白纱黑西装、干净影棚、通透柔光 |
| `french_vintage` | 法式复古 | 复古礼服、巴黎街角、胶片色调 |
| `forest_natural` | 森系自然 | 草地、树林、林间阳光 |
| `seaside_sunset` | 海边日落 | 海岸、晚霞、黄金时刻 |
| `chinese_traditional` | 中式国风 | 秀禾服、传统中式庭院 |
| `cinematic_light` | 高级光影 | 光影塑形、明暗对比、背景简洁 |
| `new_chinese` | 新中式 | 现代东方美学、月洞门、竹影、素雅 |
| `hongkong_retro` | 港风复古 | 90 年代港片色调、老街、霓虹 |
| `city_night` | 城市夜景 | 天台、城市灯火、虚化光斑 |

## 5. 完整示例

`cinematic_light`，`prompt_only`，比例 3:4，镜头为 AI 导演选择「百叶窗条纹」变体写出的一个示例（`shot_size = medium`）：

```text
竖构图，3:4 比例的写实婚纱照。

图片角色：第一张图是新娘的身份参考，第二张图是新郎的身份参考。严格保持两人的长相：脸型、五官比例、眼型、鼻型、唇形、肤色、发际线和年龄感都与第一、二张参考照片一致；不要美颜、瘦脸、磨皮或改变五官。允许改变的只有发型造型、妆容、服装、姿态、场景和光线。风格要求与长相冲突时，以长相为准。

服装与风格：新娘：光洁的低盘发，没有碎发；干净的底妆，大地色眼妆，裸色唇妆；简洁的钻石耳钉，不戴头纱；极简缎面婚纱，一字肩、收腰，没有任何蕾丝和装饰，缎面在光下有柔和的光泽，裙摆垂顺及地。新郎：整齐的背头；黑色戗驳领礼服，白衬衫，黑色领结。同一组照片里，两人的服装、发型、妆容和配饰保持完全一致。光和影是画面的主角：方向明确的光在墙面、地面和人物身上形成清晰的明暗结构或投影图案；背景简洁，颜色服务于光影；灯具等光源本身不出现在画面里。

镜头：50mm 镜头，平视机位，中景。浅灰色的墙面前，阳光穿过画面右侧的百叶窗，在墙面和两人身上落下斜向的条纹光影。两人位于画面左侧三分线附近，右侧留出布满条纹光影的墙面。新郎从身后轻轻环住新娘，新娘笑着看向镜头，新郎侧过脸看她。同一束光照亮两人和墙面，条纹落在肩膀和衣服上。

避免：网红脸、整容脸、幼态脸、五官欧美化、过度磨皮的塑料皮肤、面部被遮挡、多余的人物、手部或手指畸形、人物像抠图贴在背景上、影楼廉价感、文字和水印、脸部大面积阴影、半边脸死黑、条纹或树影横跨眼睛、剪影、过度高反差。
```

## 6. 加强长相重试（`identity_boost`）

用户觉得某张「不像本人」时使用。旧作品中的局部特写画面里没有人脸，不提供这个操作（后端返回 409 `no_faces`）。借鉴 female-portrait-director 的「保真失败后的定向重试」：强化身份锁定、降低风格化、减少遮挡和复杂动作，但保留原风格和原镜头。

在正常提示词（第 2 节）基础上做四处修改，其余（包括画面质感段）不变：

1. **人物锁定**：在该段末尾追加
   ```text
   本次是加强长相的重新生成：两人的长相比风格和动作更重要，宁可画面朴素，也要像本人。
   ```
2. **服装与风格**：在该段末尾追加
   ```text
   光线均匀柔和，降低风格化。
   ```
3. **镜头**：使用该作品原来的镜头文字（旧作品为原来的动作文字），并在句末「。」之前追加
   ```text
   ，两人面部正对或接近正对镜头，面部完整、清晰、占画面较大比例
   ```
   样片使用第 4.1 节的固定镜头，同样追加。
4. **避免项**：在风格避免项之后追加 `、侧脸、低头、头发遮挡眼睛`。

已知取舍：

- 原镜头是远景时（例如「人物位于画面下方三分之一」），与追加的「面部占画面较大比例」冲突。人物锁定段已写明「风格要求与长相冲突时，以长相为准」，模型通常会把人物拉近，构图会与原镜头不同。
- pose_06（亲吻额头）要求新郎侧脸亲吻，与「面部正对镜头」部分冲突；加强重试时新郎仍可能只露侧脸。

## 7. AI 导演（镜头编写）

用途：拍组和换动作时，由文字模型写出每张照片的镜头（PRD 3.3）。AI 导演**只写镜头正文**，其余五段仍按第 2 节组合。发给文字模型的只有文字，不包含任何照片。

### 7.1 系统提示词

```text
你是一位资深的婚纱摄影师兼导演，为一对新人设计照片。服装、视觉语言和可用的场景已由摄影团队确定，你要决定的是：每张照片在哪里拍、怎么拍。

每张照片写成一段「镜头」，依次交代：
1. 机位与焦段：机位的高低和角度，用什么焦段（例如 35mm 交代环境，85mm 压缩背景、浅景深）。
2. 构图：景别（远景、全景、中景、近景或特写），竖版还是横版，两人在画面里的位置和大小，留白在哪里，有没有前景。以竖版为主；交代环境的远景、需要横向延展的画面（例如海平面、天际线、长廊）适合横版。
3. 人与场景：使用哪个场景（有多个场景变体时选一个），写清背景、两人所在的位置和与哪个场景元素发生关系。
4. 光：这个场景的光从哪个方向照到两人身上，同一束光也照在周围的环境上；灯具等光源本身不要出现在画面里。
5. 瞬间：一个真实发生的小事件，写清动作、互动、表情和视线落点。

必须遵守：
1. 不描述任何五官或长相（例如眼睛、脸型、鼻子、嘴唇、皮肤），长相由参考照片决定。
2. 两人的面部清晰可见，不被手、头发、捧花、头纱或道具遮挡；不要背对镜头，不要剪影。
3. 不写服装；光只能来自所选场景里的光源。
4. 动作自然、真实可拍，避免多人、复杂道具和夸张特技。
5. 表情自然、真实，符合这个瞬间的情绪；整组的表情要有变化。
6. 各个镜头彼此不同，也不要与「已拍过的镜头」重复。
7. 只写具体的拍摄决定；整体画质与质感已写在发给生图模型的画面质感段里，镜头里不必重复。
8. 只输出 JSON，不要输出任何其他文字。

写法示例（只示意写法，不要照搬内容）：
50mm 镜头，略高于两人视线，中景。旧书房的窗边，午后的阳光从画面左侧的窗户斜射进来，照亮两人和身后的书架。两人位于画面左侧，右侧留出被阳光照亮的书架。新郎从身后轻轻环住新娘，在她耳边说了句悄悄话，她笑着侧过脸看他，新郎看向镜头。
```

表情和景别分布都不做后端校验：它们是创作判断，硬性规则会逼导演为了过校验改写镜头。

### 7.2 用户消息模板

```text
风格：{风格名}
{场景块}
需要的镜头数量：{N}
景别要求：{景别要求}
已拍过的镜头（不要重复）：{标题列表，用「、」连接；没有则写「无」}

请输出 JSON：{"moments": [{"title": "2～12 个汉字的标题", "shot_size": "wide | full | medium | close | extreme_close", "orientation": "portrait | landscape", "text": "镜头描述，最多 220 个字，以句号结尾"}]}
shot_size 含义：wide 远景（人物很小，环境为主），full 全景（全身入画），medium 中景（膝盖或腰部以上），close 近景（胸口以上），extreme_close 特写（只拍面部）。orientation 含义：portrait 竖版，landscape 横版。
```

`orientation` 缺失或不是这两个值时视为不合格，按第 7.4 节重写。后端**不校验横竖的数量比例**，理由与景别相同；用户可在方案预览中逐张切换横竖（只改画幅，不改描述文字）。

场景块按当前的拍组参考方式（设置项 `batch_reference_mode`）决定。

**只用两人照片（`prompt_only`）**：列出全部场景变体，导演为每个镜头选一个。

```text
视觉语言（摄影团队已确定）：{视觉语言}
场景变体（每个镜头选其中一个，并在镜头里写清背景和光影；整组尽量用到不同的变体）：
1. {变体名}：{变体文字}
2. …
```

**两人照片 + 样片（`with_preview`）**：只给第一个场景变体。样片就是在这个场景里拍的，并且会作为参考图传给生图模型；如果镜头写的是另一个场景，文字和参考图会互相拉扯。

```text
视觉语言（摄影团队已确定）：{视觉语言}
场景（所有镜头都在这个场景里）：{第一个场景变体}
```

参考方式在**导演写方案时**读取。写好方案后再切换参考方式，已有方案不会重写；需要时可在方案里逐张「换一个」。

景别要求：

| N | 文字 |
|---|---|
| 1 | `不限，选择最适合这个场景的景别和机位。` |
| ≥ 2 | `整组要像一次真实的拍摄：有交代环境的远景或全景，有互动的中景，有情绪的近景或特写；景别、机位和构图都要有变化，不要每张都是两人并排面对镜头。` |

景别要求只是给导演的建议，后端**不校验景别数量分布**：构图是创意决定，硬性配额会逼导演为凑数改动作。景别是否合心意由用户在方案预览中判断并逐张切换。

拍组时 N 为 4/8/12/20；换动作时 N = 1；多选换动作时 N 为所选张数。

### 7.3 禁用词

`text` 或 `title` 中出现以下任一词时视为不合格（描述五官或遮挡面部）：

```text
眼睛、眼型、眼神清澈、双眼皮、单眼皮、丹凤、杏眼、桃花眼、睫毛、眉毛、眉形、鼻子、鼻梁、鼻型、嘴唇、唇形、红唇、脸型、瓜子脸、鹅蛋脸、圆脸、尖下巴、下颌、颧骨、酒窝、雀斑、皮肤、肤色、五官、长相、背对镜头、背影、剪影、遮住脸、挡住脸、墨镜、口罩
```

「看向镜头」「闭眼微笑」这类描述动作而非长相的说法允许使用。

### 7.4 重写

后端校验不通过时，在原对话后追加一条用户消息，自动重写一次：

```text
上面的输出不符合要求：{逐条列出问题，例如「第 3 个镜头包含禁用词“背影”」「第 5 个镜头的标题与已拍过的重复」}。请修正后重新输出完整 JSON。
```

单个镜头「换一个」时：数量 1，景别要求为 `保持 {原景别的中文名}。`，已拍过的镜头列表加入本方案中其他镜头的标题和被替换镜头的标题。

### 7.5 改写景别

导演方案中切换某个镜头的景别，以及相册中「换景别」时，用户消息改为：

```text
风格：{风格名}
{场景块，同第 7.2 节}
原来的镜头：{原镜头正文}
请保持这个镜头里的瞬间（动作、互动、视线）和人物在场景中的位置不变，只把景别改为{目标景别中文名}，并相应调整机位、焦段和构图（例如远景让人物变小、交代环境，全景要交代脚下和站姿，近景只保留胸口以上）。画幅保持{竖版或横版}。标题可以保留或微调。
只输出 JSON：{"moments": [{"title": "…", "shot_size": "{目标景别代码}", "orientation": "{原画幅代码}", "text": "…"}]}
```

返回的 `shot_size` 不等于目标景别，或 `orientation` 与原画幅不同时，视为不合格，按第 7.4 节重写一次。

### 7.6 模拟导演

模拟生图模式下不调用文字模型，按顺序循环返回一组固定的示例镜头（覆盖四种景别），以便开发和测试不产生费用；示例镜头同样必须通过第 7.3 节校验。
